# Phase 4 비주얼 패스 설계

**Goal:** 계획서(`~/.claude/plans/breezy-painting-patterson.md`) 5절이 "레퍼런스 확보 후"로
미뤄 둔 비주얼 방향을 확정하고, 화면 전체에 일관된 토큰 체계를 입힌다.

**배경:** Phase 1–3이 `main`에 올라가 있고 기능은 다 돈다. 그러나 `src/index.css`는 아직
`@import "tailwindcss";` 한 줄이고, `KeywordGraph.tsx` 상단의 카테고리 6색·클러스터 틴트·
톱 스토리 앰버·급상승 앰버는 전부 "Provisional. Phase 4 settles the real palette" 주석을
달고 있다. 컨트롤류(날짜 스테퍼, 카테고리 탭, 재시도 버튼)는 기본 회색 유틸리티라, 그래프에만
색을 입히면 주변 UI가 따로 논다.

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 방향 | **중립 분석 도구** — 밝은 바탕, 절제된 정성 팔레트. 신문 편집면(세리프·종이톤)과 다크 관측소는 탈락 |
| 폰트 | **웹폰트 없음.** 시스템 산세리프 스택 |
| 토큰 | `src/index.css`의 `@theme` 블록. Tailwind v4 Vite 플러그인 방식이라 config 파일은 없다 |
| 다크 모드 | **범위 밖.** 토큰 구조만 나중에 얹을 수 있게 짠다 |
| 레이아웃 | 상단 스티키 툴바 + 넓은 그래프 + 기존 드로어/바텀시트 |
| 그래프 라벨 폰트 | **변경 없음** |

다크 관측소를 뺀 이유는 그래프가 아니라 패널 때문이다. 헤드라인 패널은 한글 본문 링크가
수십 줄 쌓이는 곳이라 어두운 바탕에서 읽기 나빠진다. 그래프만 보면 다크가 이기고 화면
전체로 보면 진다.

## 범위

**포함:** 색 토큰과 팔레트 재선정, 타이포 스택, 상단 툴바 레이아웃, 컨트롤·패널·스켈레톤의
외관, 템플릿 잔재 정리.

**제외 (의도적):**

- **다크 모드.** 팔레트 대비 검증을 두 벌 해야 해서 이 Phase를 두 배로 만든다.
- **그래프 라벨 폰트.** 아래 타이포 절 참조 — 바꾸면 라벨이 겹친다.
- **힘 시뮬레이션 파라미터와 `MAX_FONT_SIZE`.** 계획서가 상향을 검토하라고 한 건 어두운
  배경으로 갈 때의 이야기다. 밝은 바탕을 유지하므로 근거가 사라진다.
- **좌측 사이드 레일.** 상단 툴바가 더 흔한 모양이고, 세로 쌓기에서 벗어나는 효과는 같다.
- **단어 선정·크기·군집 계산.** 시각 층만 건드린다. 체와 레이아웃 산술은 그대로다.

## 색

### 지금 팔레트의 실제 결함

`CATEGORY_COLORS` 여섯 값의 색상환 각도를 재면 이렇다.

| 카테고리 | 값 | hue |
|---|---|---|
| 정치 politics | `#b45309` | 32° |
| 경제 economy | `#047857` | 166° |
| 세계 world | `#0e7490` | 193° |
| 사회 society | `#1d4ed8` | 224° |
| IT/과학 it | `#4338ca` | 246° |
| 생활/문화 culture | `#a21caf` | 294° |

여섯 중 **넷이 166°–246°, 폭 80° 안에 몰려 있고** 사회와 IT는 22° 차이다. '전체' 보기에서
경제·세계·사회·IT를 색으로 구분할 수 없다. 팔레트를 다시 고르는 이유는 취향이 아니라 이것이다.

### 제약

새 팔레트가 만족해야 하는 조건이다. 구현은 이 조건을 계산으로 확인한 뒤 값을 확정한다.

1. **6색의 hue 간격 최소 40°** (같은 명도대에서). 위 결함의 직접적인 해소 조건.
2. **바탕 대비 4.5:1 이상.** 최소 라벨이 14px(`MIN_FONT_SIZE`)이라 large-text 3:1 기준을
   쓸 수 없다. `faded` 단어(투명도 0.38)는 예외 — 흐리게 보이는 것이 그 상태의 목적이다.
3. **급상승 마커 색은 카테고리 6색이 쓰지 않는 hue 대역에서 예약한다.** 마커 `▲`는 단어
   바로 옆에 붙으므로 그 단어의 카테고리 색과 같으면 글자의 일부로 읽힌다.
4. **톱 스토리 워시는 카테고리 hue와 겹쳐도 된다.** 저투명 `fill`이라 역할도 렌더도 다르다.

미결로 남기는 것: **정확한 hex 값.** 어두운 노랑은 sRGB에서 주황 쪽으로 압축되어(#854D0E의
hue는 60°가 아니라 23°다) 60° 간격 6분할이 그대로는 성립하지 않는다. 노랑 자리는 hue 대신
명도로 구분해야 할 수 있고, 이 판단은 대비를 실제로 계산한 뒤에 내린다.

### 클러스터 음영

지금은 일반 클러스터 전부 `#6366f1` 0.07, 톱 스토리만 `#f59e0b` 0.18이다. 코드 주석이 적어
둔 문제 — 인접한 블롭 두 개가 겹치면 0.14가 되어 톱 스토리의 0.18과 구분이 안 된다 — 를
**투명도가 아니라 색상으로** 푼다.

- 일반 클러스터: 중립 회색 워시
- 톱 스토리: 파랑 하나

회색 두 겹은 아무리 겹쳐도 파랑이 되지 않는다. 실패 모드가 튜닝이 아니라 구조로 사라진다.

## 타이포

`--font-sans`에 시스템 스택을 둔다: `ui-sans-serif, system-ui, "Apple SD Gothic Neo",
"Malgun Gothic", sans-serif`. 웹폰트를 안 쓰므로 로딩 비용도 FOUT도 없다.

**그래프 라벨은 여기서 제외된다.** `KeywordGraph.tsx`의 `FONT_FAMILY = 'sans-serif'`는
canvas `measureText`와 `<text fontFamily>`가 **같은 문자열**을 써야 측정한 폭과 그려진 폭이
맞는다. 어긋나면 충돌 판정이 틀려 라벨이 겹친다. `<text>`가 패밀리를 명시하고 있어 페이지
폰트를 바꿔도 영향이 없고, 이 상수는 건드리지 않는다.

## 레이아웃

**데스크톱:** 스티키 상단 툴바 — 제목 왼쪽, 날짜 스테퍼와 카테고리 탭 오른쪽. 그 아래 그래프가
폭을 넓게 쓰고, 헤드라인은 기존 우측 드로어.

**모바일:** 툴바가 두 줄로 접히고(제목 + 스테퍼 / 탭), 헤드라인은 Phase 3이 깔아 둔 바텀시트
그대로.

두 가지를 지킨다.

- **패널은 `fixed` 오버레이로 유지한다.** 문서 흐름에 넣어 그래프 폭을 줄이면
  `ResizeObserver`가 새 폭을 물고 `computeGraphLayout`이 다시 돈다 — 단어를 누를 때마다
  그래프 전체가 재배치된다. 지금 오버레이인 것은 우연이 아니라 요구사항이다.
- **데스크톱 패널을 툴바 아래에서 시작시킨다.** 지금은 `sm:top-0`이라 헤더까지 덮어서, 단어를
  고른 상태에서는 날짜와 탭에 손이 닿지 않는다.

## 마크업 계약

e2e 27개는 **색도 CSS 클래스도 검사하지 않는다**(전수 확인함). 대신 구조와 텍스트를 잡는다.
아래는 이번 작업이 깨면 안 되는 목록이다.

- **`<nav>`는 `CategoryTabs` 하나뿐이어야 한다.** `smoke.spec.ts:19`가
  `getByRole('navigation').getByRole('button')`을 7개로 센다. 날짜 스테퍼를 `<nav>`로 감싸면
  strict mode 위반으로 깨진다.
- `<aside>`(complementary) — 헤드라인 패널
- `svg text` / `svg line` / `svg polygon` — 라벨 / 간선 / 클러스터 헐
- `input[type="date"]` — 네이티브 date 입력 유지
- `data-testid`: `graph-skeleton`, `headline-skeleton`
- 단어 버튼의 `aria-label` 형식: `단어, N건[, 급상승 문구]`
- 텍스트 그대로: `오늘의 주요 뉴스 스크랩`(heading), `오늘의 톱 스토리`,
  `직전 수집일 대비 급상승`, `아직 수집된 데이터가 없습니다.`, `관련 헤드라인이 없습니다.`,
  `다시 시도`, `닫기`, `이전 수집일`, `다음 수집일`

## 검증

- `npm run build` — 네 tsconfig 프로젝트 전부 타입 체크. 이것이 진짜 게이트다.
- `npm test` — 이번 작업은 산술을 건드리지 않으므로 전부 그대로 통과해야 한다.
- `npm run test:e2e` — **전부 통과해야 한다.** 셀렉터가 깨지면 위 계약을 어겼거나 마크업을
  필요 이상으로 건드린 신호로 본다. `.env` 없으면 smoke 1개가 별개 사유로 실패하고,
  `reuseExistingServer: true`이므로 먼저 dev 서버를 내린다.
- 대비 계산 — 카테고리 6색과 ink 3단계를 바탕 대비 4.5:1로 확인. 통과 못 하면 값을 조정한다.
- 눈으로 볼 것 두 가지: '전체' 보기에서 여섯 카테고리가 서로 구분되는가, 그리고 클러스터
  블롭이 두 개 겹친 자리가 톱 스토리로 오인되지 않는가.
